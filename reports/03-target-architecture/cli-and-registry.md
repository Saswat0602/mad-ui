# Target CLI and Registry

Mad UI advertises two distribution models: an npm package and "copy the source into your repo" (shadcn style). The package works with caveats. The copy path is broken today (see [../01-current-state/build-and-packaging.md](../01-current-state/build-and-packaging.md#p2-the-copy-cli-does-not-work)).

## Recommendation: publish a shadcn-compatible registry first

The shadcn CLI supports third-party registries. If Mad UI publishes registry JSON in the shadcn format, users get copy-paste installs with zero custom tooling:

```bash
npx shadcn@latest add https://mad-ui.vercel.app/r/dialog.json
```

Each registry item declares its files, npm dependencies, other registry items it needs and CSS variables, so the shadcn CLI resolves the full tree, rewrites import aliases to the user's `components.json`, and merges theme variables.

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "dialog",
  "type": "registry:ui",
  "title": "Dialog",
  "description": "A modal window that traps focus.",
  "dependencies": ["@radix-ui/react-dialog", "lucide-react"],
  "registryDependencies": ["https://mad-ui.vercel.app/r/utils.json"],
  "files": [
    { "path": "registry/mad-ui/dialog.tsx", "type": "registry:ui" }
  ],
  "cssVars": {
    "light": { "overlay": "oklch(0 0 0 / 50%)" },
    "dark": { "overlay": "oklch(0 0 0 / 70%)" }
  }
}
```

The registry is generated by codegen from `packages/react/src/components/*` and the `*.meta.ts` files, so it can never disagree with the npm package.

Static hosting: `apps/docs/public/r/*.json`, served by the docs site.

## Own CLI (phase 2)

A thin `mad-ui` CLI on top of the same registry for features shadcn's CLI does not cover:

| Command | Purpose |
| --- | --- |
| `mad-ui init` | Detect framework and Tailwind version, write `theme.css` import, `@source` line or v3 preset, `cn` helper, `components.json` |
| `mad-ui add <name...>` | Same as shadcn add, plus `--category forms` and `--all` (what the README promises today) |
| `mad-ui diff <name>` | Show what changed upstream since the user copied a component |
| `mad-ui upgrade` | Apply codemods for breaking changes between majors |
| `mad-ui theme` | Pull a theme exported from the docs theme builder |

Implementation notes:

- Node 18+, ESM, published as its own package `@mad-ui/cli` (or the `bin` of `mad-ui-components`, but a separate package keeps the library install small).
- Use `commander` or `citty` for args, `prompts` for interactive choices, `ts-morph` for import rewriting.
- Every command has an integration test that runs against a fixture Next.js and Vite app in CI.

## Blocks

Blocks are multi-file registry items (`type: "registry:block"`) such as:

- `dashboard-01`: sidebar plus header plus stat cards plus data table
- `auth-sso`: sign-in with SSO providers and work email
- `settings-security`: 2FA setup, sessions list, API keys
- `billing-portal`: plan picker, invoices table, payment method
- `team-members`: invite dialog, roles table, pending invites

These replace today's `Navbar`, `Sidebar` and `Layout` mega-components, which belong in user code where they can be edited freely, not behind 60+ props. They also match the "authentic enterprise patterns" rule in [AGENTS.md](../../AGENTS.md) section 11.
